# Agent client package

`agent` is the installable macOS CodeHarness runtime. It owns configuration, model adapters and logical profiles, the single-agent candidate loop, the HTTP-only MiniOJ client, tool execution, per-task workspace, State, and Trace.

It must not import MiniOJ internals, access MiniOJ storage/testcases, or execute submitted programs locally. Phase 1 adds typed OJ HTTP; Phase 2 adds Provider/Profile routing, Role policy, safe accounting and a guarded model probe. Phase 3 adds strict one-call/one-submit code-only with durable terminals and model/code/submission/verdict linkage; a real `t1001` task reached AC.

Phase 4 uses `core/harness.py` for fixed transitions, public-sample gates, three-failed-DEBUG replanning and local read-only REVIEW after AC; escalation is disabled. Each independent task has ten formal POST attempts and a configurable default 1-CNY reservation cap (`--max-cost-cny`, YAML or Dashboard). Missing prices/bounds prevents paid calls. Checkpoints retain Context, config, operation journals and cached responses; resume preserves the original budget and never repeats uncertain requests. Known IDs can continue polling. Versioned traces link candidates, samples, feedback, calls, hashes and budgets.

`execution.py` provides the shared Phase 5 experiment/Dashboard entry, freezes actual conditions and records observed feedback. Direct code-only CLI/compatibility entries also enforce `core/budget.py` without adding sample/retry calls. New shared requests, formal experiments and Dashboard require verdict_only by default, never substitute expectation for missing server metadata, and stop before paid calls when unverified. Explicit full remains a separate supported condition; saved tasks keep their original expectation. Direct low-level Agent CLI entries do not add this metadata gate.

`oj_client/feedback.py` implements `formal_verdict_only_v1`: declared full is accepted for expected verdict_only, with actual=full/effective=verdict_only. `ToolRuntime` projects every formal result before tracing/returning it, dropping all remote prose and extra fields, including arbitrary future keys; classified formal errors withhold remote details. Public sample runs are unchanged. State/result/checkpoints/reports retain both modes and the policy. Old exact-verdict-only fingerprints cannot resume into the new policy; explicit full and unverified smoke behavior remain separate.

Mock acceptance is complete. Phase 5 live T1003 evidence covers paid generation, a failed public sample and DEBUG, then safe invalid-output termination; zero formal submissions, no live AC claim. Batch scheduling and reports live in `experiments/`; Dashboard only queues bounded requests into this shared service. That 2026-10-01 snapshot remains unknown. Read-only inspection on 2026-10-02 confirmed me#feedback_mode=full; native verdict_only is still unverified.

New Harness tasks freeze `core/checker.py` sample_check_v1. Trusted exact/token/explicit-float checks may reject; special/unknown never becomes WA from reference mismatch. `core/generated_checker.py` uses the same CODE route with a distinct purpose to generate an unverified checker; only MiniOJ executes it. Positive approval permits formal submission; rejection/unknown stays unverifiable without DEBUG. It consumes normal model/cost limits and remote-run counts. Legacy checkpoint comparison stays unchanged.

`core/metrics.py` derives causal recovery from ordered candidate/call/hash/submission/verdict/review links, excludes infrastructure and unverified checker rejection, and reports unknown when Trace is incomplete. `models/evidence.py` separates configured model facts from unverified supplier evidence. The shared execution snapshot freezes sample policy and model evidence.

# Experiment protocol

Only five conditions are planned: standard code-only, standard harness, strong code-only, strong harness, and mixed harness (PLAN strong; CODE/DEBUG standard). No model upgrades, model REVIEW or test generation. A preparation command validates/freezes configuration and exports the task plan without any LLM, Custom Run or formal POST.

## Experiment Preflight

`preflight` is independent of ExecutionService/solve. It reads local files and only allows MiniOJ `/me`, public problem metadata, sanitized public problem GETs and the used provider's compatible `/models` GET. No completions, generated checker calls, Custom Runs, formal submissions or paid requests occur. `--offline` sends no GETs and remains BLOCKED when feedback is unknown. Existing IDs and reports are never overwritten; invalid local configuration still produces a BLOCKED report. The command returns 0 for READY/READY_WITH_WARNINGS and 2 for BLOCKED.

```bash
uv run codeharness-experiment preflight config/experiment.small.yaml \
  --experiment-id small-preflight-20261002
uv run codeharness-experiment preflight config/experiment.pilot.yaml \
  --experiment-id pilot-preflight-20261002
```

Each ID creates only `workspace/.experiments/ID/preflight/`: `preflight.json`, `preflight.md`, `execution-order.json`, `model-snapshot.json`, `prompt-snapshot.json`, and `checker-summary.json`. It does not create task State/Trace or start a batch. The report includes per-item status, blockers, warnings, GET audit and explicit zero paid side effects; artifact content hashes and the report hash protect the saved bundle.

Checker resolution mirrors the current runtime: explicit experiment override, advertised sanitized/public metadata, then unknown. `tokens` maps to token, `testlib` to special; `lines`/`yesno` stay unknown. Text about error bounds cannot establish float tolerances. Both explicit absolute and relative tolerances are required for client-verifiable float checking. The source path and checker_resolution_source separately identify metadata provenance and an explicit override. Missing metadata is a warning; conflicting known checker metadata or frozen rating drift is a blocker.

The report preserves checker kind independently of provenance/verification. Main sample_check_v3 uses semantic_check for exact/token/float with both trusted explicit tolerances, and execution_only for special/unknown/incomplete float without a verified semantic adapter. Execution-only rows show semantic_verification=unavailable, formal_fallback=enabled and requires_llm_checker=false. A known Custom Run OK with integer exit_code=0 records output_unverifiable (passed=null), then allows formal evaluation after all public samples; stdout equality is irrelevant. CE/RE/TLE/MLE/OLE or nonzero exit enters DEBUG as sample_execution_failure. Unknown/IE/HTTP/protocol failures stop without DEBUG, formal or retry. There is no wired public remote sample judge. The legal execution path does not claim sample semantics or checker certification. Historical v1/v2 strata and positive-only LLM gates remain available only under their frozen policies; their stop+disabled/advisory path still blocks. No problems are removed.

Only actually routed PLAN/CODE/DEBUG profiles receive provider/budget checks. Harness's existing local REVIEW checkpoint definition, when distinct, is resolved as a runtime_snapshot_profile_dependency without metadata queries or model REVIEW; its checkpoint contract is preserved. Guarded CLI runs use the same selected-profile loader as preflight. `/models` ID presence proves availability alone. Positive integer max_output_tokens/context_window/input_limit fields, if explicitly advertised by a compatible metadata response, are independently recorded with field sources/time. Price evidence requires explicit pricing.{input_price,output_price,currency,unit=per_million_tokens}; unrecognized units/aliases remain unknown. Missing, malformed or paginated metadata cannot establish absence. Local prices/output requests/input reservation bounds never populate verified fields. Unknown limits set needs_live_probe=true; no live generation probe is performed. Unspecified temperature/top_p remain null and warn that provider defaults are not frozen as known values.

Budget checks require finite CNY prices and positive reservation/output bounds, affordable minimum startup calls, sufficient call caps, and enough batch allocation for every prepared task to retain the same cap. They do not estimate actual spend. Unknown supplier prices/limits and git dirty are warnings. Unknown feedback, unresolved required models/profiles, unavailable listed models, invalid ordering, missing prompts, invalid budgets and inconsistent fingerprints are blockers. Explicit full under formal_verdict_only_v1 satisfies expected/effective verdict_only and is READY.

Prompt snapshots contain the system text, rendered placeholder PLAN/CODE/DEBUG/sample-checker messages, prompt_name/version/sha256, and the full dynamic assembly source. Assembly policies include feedback clipping, recent history bounds and the CODE checker route. This freezes template content rather than file paths; public problem input content is separately hashed. No model REVIEW/Test Generation is activated.

The experiment fingerprint includes Git commit, dirty state and dirty diff hash (staged/unstaged diff plus untracked file content), parsed/raw experiment config hashes, problem list, configured model snapshot and model file, harness config, prompt bundle, loaded runtime source hash, formal_submission_dedup_policy, checker/feedback policy hash/version, execution version/seed/order hash, and OJ/provider endpoint fingerprints. Git root is resolved from the experiment configuration/caller, while the runtime source hash covers the loaded package, including wheel installations. Verification timestamps do not change the configured condition hash; the full evidence bundle remains frozen by its report hash. Credential values and raw endpoints are not saved.

The default execution seed is **20261002**. problem_blocks_balanced_sha256_v1 retains problem blocks, ranks condition names by seed/cycle SHA-256, then rotates positions over each five-problem cycle. Every condition occupies every position once per complete cycle. All 60 task pairs occur exactly once, and different problems receive varying order. An explicit --execution-seed or YAML execution_seed is saved; it is never regenerated randomly. This is an execution-order seed, not a model sampling seed.

Prepared main/pilot configurations require --preflight-id for run. The paid run must use a distinct new experiment ID and retain the existing two confirmation flags; the preflight itself is not authorization. Resume binds the original preflight ID/report hash and never replaces it. Start, resume and each subsequent task check the current local fingerprint; each task rechecks explicit account feedback and the frozen public problem input hash when available. Drift refuses further execution and requires new preflight/experiment IDs. Original historical runs retain their old signatures/order; no State/Trace/results are migrated or rewritten. Editing or committing this dirty tree invalidates its frozen fingerprint.

`config/experiment.pilot.yaml` froze CF2127C/CF2125D/CF2127D: public token checkers, ratings 1400/1600/1800, five conditions, one repetition, 15 tasks and 15 CNY allocation. Its original run is immutable diagnostic evidence (9 completed, 6 infrastructure failures); its fingerprint is never reused for changed runtime conditions. Infrastructure qualification used a separate four-task config, clean commit/preflight and artifacts. Its original INFRA_NOT_READY result is preserved: the sole blocker was duplicate byte-identical formal submissions within a task. The authorized dedup fix uses deterministic local validation, a separate clean commit and new Pilot-v2 preflight; its independent READY_FOR_PILOT_V2 gate requires same-task/resume dedup, feedback projection, correct counters, clean Git and a matching new freeze. Executing all 15 Pilot-v2 tasks requires later explicit authorization. Neither qualification nor old/new Pilot results authorize the 60-task main experiment.

`config/models.infrastructure.yaml` explicitly configures the shared provider's 600-second connect/read/write/pool inactivity timeouts, no overall wall deadline and no automatic retries. Model JSON remains non-streaming; transport body observation does not enable model streaming. `input_reservation_boundary=65536` is a conservative local input/cost reservation for standard/strong, independently of unverified provider context/max-input. Legacy `input_token_limit` retains its local meaning; specifying both keys is rejected. Requested output stays 8192. Route snapshots/preflight freeze actual transport settings and budget bounds, so changes require a new fingerprint. `MODEL_BUDGET_CHECK` records allowed/rejected decisions and byte-based Prompt decomposition without modifying messages; component token counts stay null without an authoritative tokenizer. Model responses retain the raw response model ID, numeric usage metadata and allowlisted network observations. See [infrastructure evidence](evidence/20261002-infrastructure-qualification.md).

Local/MockTransport validation and read-only service evidence are recorded in [the preflight evidence](evidence/20261002-preflight.md).

### Main Final Receipt

The original 12 × 5 × 1 layout requires `main_final_receipt_v1`, in addition to the ordinary frozen preflight and explicit run confirmation flags. Produce it without starting a batch:

```bash
codeharness-experiment preflight config/experiment.small.yaml \
  --experiment-id main-v1-preflight-20261003-final \
  --main-experiment-id main-v1-20261003 \
  --pilot-run-id pilot-v2-live-20261003
```

The standard directory adds `final-receipt.json`, `freeze-diff.json`, `checker-matrix.json` and `budget-summary.json` to the existing six files. Artifact content hashes are bound by the preflight report hash; the receipt additionally binds the report content, future Main ID, fingerprint, Git/dirty diff, counts, list/order/seed, prompt/models and checker/feedback/dedup versions. Gate is `MAIN_V1_READY`, `MAIN_V1_READY_WITH_WARNINGS` or `MAIN_V1_BLOCKED`; execution_authorized remains false. The Runner verifies receipt association after the current local fingerprint check and before batch creation/HTTP, on resume and before later tasks. It never regenerates preflight automatically. New edits or commits require new IDs and evidence. Existing historical artifacts are not migrated.

Validated Pilot-v2 receipt/validation/manifest/preflight are read only and independently hash-bound. Shared Agent sources, prompts, model IDs/parameters/bounds/transport/prices, Harness budget/rules, global sample policy, shared checker specs, feedback and task-local dedup must match, except the explicitly authorized versioned checker changes described below. Different Main list/order/allocation and additive preflight/report code receive a new fingerprint and are described item by item as same/changed/not_applicable. The earlier infrastructure authorization changed only the Main YAML model_config reference to models.infrastructure.yaml; the subsequent v3 authorization changes only Main sample policy version/LLM disabling/execution-only fallback; user .env/models.yaml/harness.yaml are preserved. No Pilot-driven tuning occurred.

CF2127C/CF2125D/CF2127D are pilot_seen=true with pilot_run_id; other main problems are false. The marker is evaluation metadata, never prompt context. Main task IDs/workspaces/model calls/candidates/submissions are new; no Pilot checkpoint/response/source/verdict/cache is loaded into execution. Main exports pilot-subsets.json with all_problems/pilot_seen/pilot_unseen, retaining the existing condition/feedback/checker comparison boundaries. Older rows without contamination evidence remain null, not automatically unseen.

Checker matrix preserves exact/token/float/special/unknown kinds; llm_generated_unverified is a verification class, not a new CheckerSpec kind. The classes are client_verified/remote_verified/llm_generated_unverified/unverifiable with explicit problem lists. Live coverage requires a validated Pilot sample path and matching frozen public input/spec. Uncovered legal paths warn and set live_validation_required=true; an impossible path blocks. No live checker smoke/completion/Custom Run/formal POST is part of final preflight. Unknown feedback, inaccessible problem inputs or unresolved model availability block final-main readiness. See [Main evidence](evidence/20261003-main-final-preflight.md).

## Results and earlier preparation

Task rows include condition, actual_models, checker_type/source/policy/stratum and checker_applicability (disabled for code-only). Candidate versions retain Trace version/hash/model-call links; custom_runs and formal_submissions are explicit aliases of Trace-derived counts. LLM call counts come from Trace with an incomplete-trace status when applicable; token usage and CNY cost require correlated call/response events, and unknown usage is not filled with zero. New TASK_TERMINATED events carry measured wall time; old Trace without that field keeps wall_time=null and its original wall_clock_seconds projection. Neither these aliases nor report projections rewrite historical State/Trace. Strict recovery definitions below are unchanged, and no per-task/per-condition Performance is created.

Rows also keep cached_tokens from correlated numeric prompt_tokens_details.cached_tokens (missing remains null), provider_reported_cost/billed_cost (currently null), response finish_reason/model/usage metadata and existing candidate extraction links. Cached input remains included in total input; no undocumented cache discount is assumed. all_formal_verdict_observations preserves every intermediate confirmed result with candidate/submission links; task_final_outcome is exclusive, so TLE→DEBUG→AC counts final AC while retaining TLE, and an earlier WA followed by invalid_model_output/budget_exhausted does not become a final WA. Recovery still requires the existing causal DEBUG/REVIEW evidence; no prompt/parser/budget tuning or injected failures is introduced.

New Harness tasks freeze task_source_bytes_v1: task/problem/frozen sanitized problem/language/exact submitted UTF-8 SHA identity. A confirmed task-local cache hit reuses the original structured observation through the frozen feedback policy and records FORMAL_RESULT_REUSED, with current candidate links and original source submission/version/model call. LLM calls, candidate versions and DEBUG iterations still count; duplicate_candidate_count and formal_result_reuse_count are Trace-derived and audited. Formal submission/attempt counters and formal remote requests do not increase on a completed cache hit. A→B→A submits A and B once each; separate tasks remain independent. Only formal submissions fill this persistent checkpoint cache; Custom Run is unaffected. Pending unknown POST intents fail closed, known IDs resume polling, and the existing task lock prevents concurrent cache misses. There is no repetition early stop or new result-based heuristic, and cached acceptance does not create a new algorithm-recovery chain. See [dedup evidence](evidence/20261003-formal-dedup.md).

The small set targets 12 problems: 3 each at 1200/1400/1600/1800, one repetition, 60 independent tasks. Public MiniOJ ratings are recorded with source and fetch time; unknown stays null. Metadata is evaluation-only and is not added to the sanitized Agent prompt. Task budgets remain independent, with an explicit batch allocation ceiling; the ceiling is not estimated spend or authorization to run.

Task/report metrics derive from ordered Trace events with candidate version, SHA-256, model call and submission identity. `first_try_ac` means the first confirmed formal submission received AC. No submission means false. `recovered_to_ac` requires a verified sample/program failure or formal program verdict, a later successful model call/response producing the accepted candidate and a final linked formal AC. IE, HTTP/provider/protocol errors and unknown POSTs are not algorithm failures. `formal_recovery_to_ac` additionally requires an intervening successful DEBUG call, its new candidate, linked AC submission and matched REVIEW. `successful_debug_count` counts the directly accepted DEBUG candidate (0 or 1), not every DEBUG candidate whose sample happens to pass. Reports preserve the evidence chain; substitute tests are not real repair validation. Incomplete Trace or counter mismatch yields null key conclusions.

LLM-generated checker observations remain unverifiable even when they permit submission. They never count as sample pass/reject or sample recovery. Reports add `llm_checker_call_count`, `checker_custom_run_count`, `contestant_custom_run_count` and `llm_checker_reject_count`; aggregate model/Custom Run counts include them. Historical token mismatches without a trusted checker do not earn new algorithm-recovery credit.

Summaries group by condition, mode/profile, recorded rating, checker policy and actual/effective feedback policy, including effective budgets and actual model configuration. Unknown usage/cost remain null. Configured prices/input bounds/output requests/generation parameters and endpoint fingerprints are distinct from supplier verification; `verified_*` stays null without independent evidence. An input reservation bound is not a verified context window.

Official Performance comes directly from `GET /api/v1/contests/{id}/standings#rows[].performance` (confirmed integer 0–4000). Match `/api/v1/me.id` to exactly one `rows[].user_id`, never row order or display name. Missing/invalid/ambiguous/unavailable data yields null with a machine status. Refreshing enrichment uses GET only and is separate from Agent execution. It records fetch time, endpoint fingerprint and account identity. Performance describes the account across the entire contest, including other runs; it is not a per-task value or isolated five-condition score. No formula is implemented.

Historical Workspace files remain unchanged. Enrichment is stored as a separate metadata artifact and merged on read; ordinary Dashboard GET/polling only reads local files. Explicit refresh requires the existing same-origin/CSRF control boundary and is unavailable in read-only mode.

Offline preparation (no confirmation flags and no execution):

```bash
uv run codeharness-experiment prepare config/experiment.small.yaml \
  --experiment-id small-prepared --output /private/tmp/codeharness-small-plan.json
# Optional --freeze-model-config loads configured provider/model/params locally,
# snapshots all five conditions, and closes clients without any HTTP requests.
```

`--output` creates a new file and refuses overwrite. The plan has `execution_authorized=false`; it is not an executed batch. A new run freezes its actual selected model snapshot and rejects drift on resume. Never substitute supplier facts for configured prices or report the allocation ceiling as actual spend.

Standalone official refresh for a run that froze its account identity:

```bash
uv run codeharness-experiment contest-performance 1 --experiment-id RUN_ID
```

This validates the saved contest ID and never initializes ExecutionService. Old runs without frozen identity stay null/identity_unresolved. A single account's cumulative contest value cannot answer which of five conditions had higher Performance; an isolated official comparison requires a later agreed service/account separation, not a client-derived formula.

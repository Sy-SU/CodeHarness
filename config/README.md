# Configuration

`models.example.yaml` is a non-secret structural example. Copy it to local `models.yaml` and replace all model placeholders before a real call. Provider timeout and allowed parameters are explicit; each Profile may define only declared parameters.

Secrets and endpoints come from environment variables listed in [`.env.example`](../.env.example). Input/output prices must be configured together with a currency; when pricing or usage is absent, cost is unknown/null rather than zero. The default mixed Role mapping is present. Current harness execution forces escalation off even if YAML enables it.

`codeharness-model-client probe` performs one guarded live call with `--confirm-call`. Phase 2 used an ephemeral `qwen3.8-flash` mapping to verify connectivity, and Phase 3 reused it only for one code-only acceptance task; it is not stored here as a formal fast/standard/strong/max decision.

`harness.example.yaml` sets ten formal POST attempts, default 1 CNY and three-failed-DEBUG replanning. `max_cost_cny` / CLI `--max-cost-cny` / Dashboard input can raise or lower the cost budget; ten submissions stays a hard task cap. The 80-call backstop and optional cumulative active-time limit remain. Both direct CLI modes enforce the budget. Resume uses the saved policy and rejects changes before calls; it does not grant fresh funds.

For every used model route, harness requires configured `input_token_limit`, `parameters.max_tokens`, paired per-million token prices and `currency: CNY`. Declare `max_tokens` in the Provider's allowed parameters. Copy actual provider-supported bounds and current prices, not guessed values. The example deliberately omits prices/input bounds; harness will stop as `budget_unverifiable` before a paid call.

The cost guard reserves the full input/output bound before each request and does not release reservations after failures, interruption or lower actual usage. This is a conservative ceiling separate from `estimated_cost` based on actual usage; it can stop early. Billing protection depends on accurate tariffs/effective bounds. Resume freezes routes, prices, bounds, Role mappings and policy; changing them is not a silent continuation of the same task.

`experiment.full.yaml` uses confirmed T1003, four fixed standard/strong × mode groups plus `mixed-harness`, one repetition each, verdict_only required, default 1 CNY per task / 5 CNY aggregate allocation cap. Its historical filename is retained; its experiment name and actual requested feedback condition are verdict-only. The template has five groups too. `experiment.smoke.yaml` retains historical two-mode/1-CNY-total/unknown-allowed conditions. Each strategy/repetition is an independent task, not a shared per-problem allowance. A positive aggregate cap is still required. CLI `--max-cost-cny` does not raise it. Model paths resolve relative to YAML. Local/template output requests are 8192 tokens, not proof of provider-supported effective bounds or tariffs.

New shared requests/experiment configs default to `expected_feedback_mode: verdict_only` and `require_feedback_mode: true`. This is a requested condition, never actual-mode evidence; unknown or mismatched metadata stops before paid calls. On 2026-10-02 `/api/v1/me` declared full. The old 2026-10-01 unknown snapshot is preserved; neither changing expectation nor that full value proves native verdict-only mode. Explicit `full` is supported for separate experiments. Historical smoke tests allow unknown only through explicit null/false settings. Existing task/config fingerprints and reports are not rewritten.

Declared server full now satisfies a new verdict-only request through versioned client filtering, not by changing actual mode: actual=full/effective=verdict_only/feedback_policy=formal_verdict_only_v1. Only formal submission ID/status/verdict reaches the Agent and persisted task data; remote summary/errors/extra fields are withheld. Public samples remain available. Missing/unknown metadata is still blocked; reverse compatibility is not allowed. The policy participates in fingerprints, so old exact-verdict-only runs need new IDs. No server permission or user YAML/credential is changed.

Local `models.yaml`, `harness.yaml`, `*.local.yaml` and `* copy.yaml` stay excluded from sdist. Dashboard defaults to local harness/selected MODEL_CONFIG; invalid policy fails before calls. Its Task configuration panel allows six new-task overrides: cost, model calls, submission attempts (at most ten), HTTP timeout, polling interval and judge deadline. Defaults come from YAML/CLI (`--max-cost-cny` overrides cost). It does not edit YAML, credentials, paths, roles, escalation, DEBUG policy or the required feedback mode; code-only locks calls/submissions to one. Jobs/checkpoints freeze all settings and resume cannot change them. Local files are preserved.

`checker.example.yaml` is an independent sample gate example: default stop for unverifiable plus LLM-generated checker positive-only submission permission. Pass/reject observations remain unverifiable, not sample pass/failure. Checker generation is a purpose-marked CODE call; rejection does not enter DEBUG. Explicit disabled/advisory and per-problem exact/token/float overrides are supported; float has no guessed tolerance. Use Agent/Dashboard `--sample-config`, or Experiment YAML `sample_checking`; saved tasks cannot change it. Browser task JSON cannot specify source or paths.

`experiment.small.yaml` is the 12-problem, five-condition, one-repetition preparation config: ratings 1200/1400/1600/1800 each three, verified public metadata with source/time. 60 independent tasks have a 60-CNY allocation ceiling; no automatic execution. `codeharness-experiment prepare ...` validates/exports without calls. Optional `--freeze-model-config` snapshots configured model/price/input/output/generation parameters and endpoint fingerprints locally. All supplier `verified_*` remain null; a configured input-token reservation bound is not a context-window fact. This round preserves local models.yaml/harness.yaml/.env. See [experiment protocol](../docs/experiment-protocol.md).
